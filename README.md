## 🔧 v4.1 - تعديلات (تمت تجربتها على نسخة محلية من صفحة Hotspot)

1. **إصلاح الخطأ الأهم (SUSPECTED MATCH زائف):**
   الفحص الاستطلاعي للصفحة الفاشلة كان يرسل 8 حروف عشوائية، فالحواجز التي
   تفرّق بين "بطاقة بصيغة خاطئة" و"بطاقة صحيحة الصيغة لكنها غلط" كانت
   ترجع صفحة مختلفة عن أي بطاقة مجرّبة → الأداة كانت توقف على أول بطاقة
   غلط وتعلنها "سUSPECTED/SUCCESS" خطأ. الآن الاستطلاع يستخدم بطاقات
   بنفس صيغة البطاقات المطلوبة (بادئة + أرقام) فيصبح الأساس صفحة الرفض
   الحقيقية وتكمل الأداة حتى تجد البطاقة الصحيحة.

2. **فخ `success_url` يساوي رابط الدخول:**
   عند بوابة ترجع 200 بدون إعادة توجيه، تعلّم الصفحة الناجحة كان يحفظ
   success_url = رابط الدخول نفسه، فتُعتبر أي رد على صفحة الدخول "نجاح"
   (خطأ إيجابي لكل البطاقات). لم يعد يُحفظ إلا إذا اختلف فعلاً عن رابط
   الدخول (وتم تنظيف ملف البروفايلات الحالي).

3. **SELF-TEST صار يميّز بين أنماط كلمة المرور:**
   بطاقة المقارنة كانت أصفاراً (صفحة صيغة خاطئة) → كل الأنماط كانت
   تظهر "ACCEPTED". الآن بطاقة مقارنة بنفس الصيغة (آخر رقم مغيّر)
   فتظهر الأنماط المرفوضة "same reply as a wrong card".

4. **User-Agent متصفح في كل التدفقات** (كانت تدفقات التشخيص ترسل
   python-requests).

**النتيجة على صفحة تجريبية مطابقة لسلوك شباكتك** (صفحتا النجاح/الفشل
بنفس الطول 8575 كما في kirapass_hits.txt): وجدت البطاقة الصحيحة
0201242548 في ~40-60 محاولة من 100 بدون أخطاء، وبلا أي خطأ إيجابي
عند سحب كامل (100/100) بدون بطاقة صحيحة.

## 📖 شرح كل خيار بالتفصيل

═══════════════════════════════════════════
 1) Enter login page link
═══════════════════════════════════════════

ماذا تدخل؟
→ رابط صفحة تسجيل الدخول للـ Hotspot.

مثال:
  http://10.5.50.1/login
  http://192.168.88.1/login.html
  http://hotspot.mynetwork.com/login

كيف تعرفه؟
→ افتح المتصفح واذهب لأي موقع، سيحولك تلقائياً
  لصفحة الـ Hotspot. انسخ الرابط من شريط العنوان.

═══════════════════════════════════════════
 2) Request Method : GET أو POST
═══════════════════════════════════════════

كيف أعرف أي واحدة أختار؟

✔ طريقة سهلة 100%:
  1. افتح صفحة تسجيل الدخول في المتصفح
  2. اضغط F12 (أو右كليك → Inspect)
  3. اذهب لتبويب "Elements"
  4. ابحث عن كلمة <form
  5. شوف method="???"
     → إذا method="post" اختار POST
     → إذا method="get"  اختار GET

✔ طريقة ثانية (سريعة):
  - راقب شريط عنوان المتصفح بعد تسجيل دخول عادي.
  - إذا رأيت كلمة username=xxx&password=xxx في الرابط
    → النوع GET
  - إذا الرابط ما تغير أو ما فيه بيانات
    → النوع POST

✔ قاعدة عامة:
  - أجهزة Mikrotik القديمة → غالباً GET
  - أجهزة Mikrotik الحديثة → غالباً POST

═══════════════════════════════════════════
 3) أسماء الحقول (عند اختيار POST)
═══════════════════════════════════════════

ماذا تدخل؟
→ أسماء الـ input fields في صفحة HTML.

كيف تعرفها؟
  1. افتح صفحة login في المتصفح
  2. اضغط F12 → Elements
  3. ابحث عن الكود:
     <input name="username">
     <input name="password">

  الاسم بين علامتي " " هو ما تدخله في الأداة.

✔ أسماء شائعة في Mikrotik:
  - username / user / usr
  - password / pass / pwd
  - dst (يُترك فارغاً عادةً)
  - popup (يكون "true" أو "false")

✔ إذا لم تكن متأكداً → اضغط Enter فقط (يستخدم الافتراضي)

═══════════════════════════════════════════
 4) Choose Network Type
═══════════════════════════════════════════

  1) only username
     → الشبكة تعتمد على username فقط (بطاقة/كود)
       بدون كلمة مرور منفصلة.
       مثال: بطاقات إنترنت في المقاهي.

  2) username and hidden password
     → username نفسه يستخدم كـ password.
       (شائع في البطاقات القديمة)

  3) username and password
     → يوجد username و password مختلفان.
       (الأكثر تعقيداً)

═══════════════════════════════════════════
 5) Success Keyword (مهم جداً)
═══════════════════════════════════════════

ما هو؟
→ كلمة تظهر في صفحة HTML بعد تسجيل دخول
  ناجح، ولا تظهر عند الفشل.

لماذا نحتاجها؟
→ الأداة تحتاج طريقة لتمييز النجاح من الفشل.
  الكلمة المفتاحية تساعد في هذا التمييز.

كيف أعرفها؟

✔ طريقة 1 (Mikrotik Hotspot القياسي):
  → اضغط Enter فقط (الافتراضي "status" يعمل
    مع أغلب أجهزة Mikrotik تلقائياً)

✔ طريقة 2 (يدوياً):
  1. سجل دخول عادي بنفسك (بنجاح)
  2. اضغط Ctrl+U لعرض صفحة HTML
  3. ابحث عن كلمة فريدة تظهر فقط عند النجاح
     مثال: "logged in", "welcome", "connected"
  4. أدخلها في الأداة

✔ طريقة 3 (من URL):
  إذا الرابط بعد النجاح يحتوي كلمة مميزة
  مثال: http://10.5.50.1/status
  → الكلمة "status" هنا تكفي

✔ إذا ما تعرف → اتركها فارغة (Enter)
  الأداة ستعتمد على r.url و r.history تلقائياً

═══════════════════════════════════════════
 6) Number of Threads
═══════════════════════════════════════════

ماذا تدخل؟
→ عدد الطلبات المتوازية (المسامية).

التوصيات:
  5-10   → آمن جداً، بطيء
  15-20  → متوازن (موصى به)
  30-40  → سريع جداً (قد يثقل الراوتر)
  50+    → خطر حظر، غير مستحسن

═══════════════════════════════════════════
 7) Number of Attempts
═══════════════════════════════════════════

→ عدد المحاولات الكلية قبل التوقف.

مثال: إذا طول البطاقة 5 أرقام
      عدد الاحتمالات = 10^5 = 100,000

✔ ابدأ بـ 500-1000 محاولة أولاً.

## 📊 قراءة النتائج

✓ FOUND
  → الأداة وجدت بيانات دخول صحيحة!

✖ Not Found in X attempts
  → لم تجد. جرب:
    - زيادة عدد المحاولات
    - تغيير الـ Success Keyword
    - التأكد من الـ Request Method

⚠ Connection Error
  → مشكلة في الشبكة أو الرابط غير صحيح
