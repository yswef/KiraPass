# لماذا توقفت الأداة القديمة؟ — التشخيص بالأدلة
### KiraPass 5 · تقرير فني مبسّط

طلبت أن تعرف **لماذا** لا تعمل الأداة، لا أن نُصلحها فقط. هذا هو التشخيص الكامل،
وكل حالة هنا **تم إثباتها بتشغيل الكود القديم فعلاً** على بوابة محلية تحاكي شبكتك،
أو بالأدلة الموجودة في مستودعك نفسه.

---

## الملخّص في سطور

الأداة القديمة كانت تعتمد على ثلاث أفكار هشّة:

1. **«صفحة مختلفة = بطاقة صحيحة»** — وهي أخطرها، وتفسّر توقفها بعد أول بطاقة.
2. **مقارنة الصفحات بالطول (±40 بايت)** — تنكسر مع أي رمز جلسة يتغيّر كل طلب.
3. **إعدادات محفوظة قديمة** — تُسقط الكود بخطأ `KeyError` غير مُلتقط.

والنتيجة: تظهر لك «SUSPECTED MATCH» أو «DIFFERENT page» بلا معنى، ولا تتعرّف
على النجاح الحقيقي (تحويل 302 إلى الإنترنت)، وتتوقف فجأة.

---

## الدليل رقم ١ — البطاقة الخاطئة تُعلن «ناجحة» (السبب الرئيسي لتوقفها)

### ما كان الكود يفعله

في دالة التخمين كان السطر الحاسم:

```python
strong = ok or verdict.startswith('DIFFERENT')
if strong:
    shared['found'] = True          # إعلان نتيجة
    stop_event.set()                # إيقاف كل شيء
```

أي أن **أي رد لا يشبه صفحة الفشل يُعتبر نجاحاً ويوقف التشغيل**. وفي شبكة POST
الحقيقية كل رد «يختلف» لأن الصفحة تحتوي رمز جلسة (session token) ومحتوى يتغيّر
مع كل طلب — فتتوقف الأداة على أول بطاقة وتقول لك «بطاقة مشتبهة».

### الإثبات

شغّلنا الكود القديم نفسه على بوابة محلية تُصدر رمز جلسة جديد كل طلب:

```
#01/12  card: 02012423304210  | HTTP 200 | same as failure
...
#01/30  card: 0201247545  | HTTP 200 | same as failure
#04/30  card: 0201248754  | HTTP 403 | BLOCKED page - your IP got banned mid-run
#06/30  card: 0201243955  | HTTP 501 | DIFFERENT page len=414
* SUSPECTED MATCH - this card got a page different from every wrong card - finishing...
=> tested=6 found=True suspected=True verdict shown to user: SUCCESS/SUSPECTED MATCH
```

لاحظ: بعد أن **حجب الراوتر الاتصال** (403) ظهر رد آخر «مختلف» فأعلنت الأداة
«SUSPECTED MATCH». أي أنها تعطي نتيجة إيجابية على شبكة حجب، وهذا يفسّر تماماً
أنك ترى أرقاماً «تنجح» ثم لا تعمل فعلاً.

### دليلك أنت

في ملف `kirapass_hits.txt` داخل مستودعك: **٩ بطاقات، كلها بنفس الطول 8575**،
ومع ذلك:

```
#1 card=0201242548 ... verdict=SUCCESS
#2..#9 card=... status=200 loc= len=8575 verdict=DIFFERENT page len=8575
```

نفس الطول تماماً وفي نفس الجولة، و٨ منها تُعلن «صفحة مختلفة». هذا يعني أن
**أساس المقارنة (baseline) لم يكن مطابقاً للصفحات التي تُقارن بها** — إمّا لأن
البطاقة التجريبية للفحص كانت بصيغة مختلفة، أو لأن المقارنة فشلت قبل أن تبدأ.
وفي كل الأحوال، حكم «مختلف = ناجح» هو ما يحوّل ذلك إلى نتيجة كاذبة.

## الدليل رقم ٢ — الراوتر يقبل البطاقة والأداة تقول «لا»

الشكل الأكثر شيوعاً للنجاح في شبكات الهوتسبوت هو:

```
HTTP/1.1 302 Found
Location: http://connectivitycheck.gstatic.com/generate_204
```

أي `302` + تحويل إلى الإنترنت = البطاقة عملت. اختبرنا الكود القديم:

```
TEST 1 - the GOOD card, judged by the tool's own is_successful()
   HTTP 302 | Location: http://connectivitycheck.gstatic.com/generate_204
   is_successful() -> False     (الراوتر أعطى إنترنت فعلياً!)
```

الدالة `is_successful()` كانت تفحص: توقيع كلمات، `success_url`، `/status`،
كلمة مفتاحية — ولم تكن تعتبر «التحويل خارج البوابة» نجاحاً. لذلك في اختبار
الاتصال الذي ذكرته (**«تقوم بالاتصال في الشبكة ولكن الأداة لا تتعرف على ذلك»**)
كان الكود يرى البطاقة الصحيحة ولا يعتبرها نجاحاً.

## الدليل رقم ٣ — انهيار بخطأ `KeyError` مع ملف تعريف قديم

هذه هي أشهر طريقة تجعل أداة «تعمل أمس ولا تعمل اليوم» بعد تحديث ملف `.py` فقط.
الكود الجديد كان يقرأ مفاتيح إضافية من الملف التعريفي المحفوظ:

```
!! _probe_pair CRASHED: KeyError 'charset'
!! attack() catches this and sets wrong_d = None
!! -> every attempt then falls through to the last branch:
!!    verdict = 'DIFFERENT page len=...'  => false SUSPECTED MATCH == stop at #1
```

وبصيغة أخرى من نفس الخطأ في دالة أخرى (غير محمية أصلاً):

```
File "KiraPass.py", line 631, in _profile_space
    return _space_size(p['charset'], p['var_len'])
KeyError: 'charset'
```

يحدث ذلك لأن الملف التعريفي المحفوظ قبل التحديث لا يحتوي `charset`/`var_len`،
فينهار الكود أو يُفسد الأساس، فتتحول كل النتائج إلى «صفحة مختلفة».

## الدليل رقم ٤ — ميزة «اختبار الاتصال» كانت كوداً ميتاً

في المستودع دالتان باسم واحد:

```
functions defined twice: ['diagnose_flow']
functions never referenced (dead code): ['top_error', 'verify_flow']
```

* `verify_flow` — وهي ميزة «اختبار نوع الاتصال/التحقق» — **لا تُستدعى من أي مكان
  في القائمة**. أي أنها معطّلة فعلياً، تماماً كما وصفت.
* `diagnose_flow` مُعرَّفة مرتين؛ النسخة الثانية (في نهاية الملف) تُلغي الأولى،
  والمستخدم يرى سلوكاً مختلفاً عن المكتوب في التوثيق.

---

## الدليل رقم ٥ — الاعتماد على مكتبة خارجية

الكود القديم يبدأ بـ`import requests`. على أي جهاز جديد (ويندوز نظيف، هاتف، جهاز
مختبر مقفل) تظهر:

```
ModuleNotFoundError: No module named 'requests'
```

وتتوقف الأداة قبل أن تبدأ. هذه ليست مشكلة شبكة، لكنها سبب شائع جداً لـ«لم تعد تعمل».

## لماذا كانت الخطوات كثيرة؟

القائمة القديمة كانت:

```
1) QUICK MODE   2) Use saved profile   3) Full setup   4) Manage profiles
5) Fetch portal scripts   6) SELF-TEST known card     0) Exit
```

* خمسة تدفّقات مختلفة لنفس العملية (سريع / ملف / كامل / تشخيص / تحقق)، كل تدفّق
  يبني الإعدادات بطريقته → اختلاف النتائج لنفس الشبكة.
* أسئلة لا يمكن للإنسان الإجابة عليها بثقة («هل ترسل dst/popup؟»، «قيمة كلمة
  المرور: 1/2/3/4/5؟»، «سداسي عشري صغير أم كبير؟») — بينما الصفحة نفسها تُخبرنا.
* التخمين يعتمد على إجابات المستخدم، وإجابة واحدة خاطئة تُفسد كل شيء بصمت.

**في KiraPass 5** صارت الخطوات أربعاً، وكل ما يمكن قراءته من صفحة الدخول
يُقرأ تلقائياً، وما يبقى سؤالين فقط: شكل الكرت، وقوة الجهد.

## كيف أُصلح ذلك في KiraPass 5

| المشكلة | المعالجة الجديدة |
|---|---|
| «مختلف = ناجح» | **لا نجاح بلا دليل**: تحويل خارج البوابة، كلمات نجاح متعلَّمة، أو اختبار إنترنت حقيقي |
| رمز جلسة يتغيّر كل طلب | **تعلّم الرموز المتغيّرة آلياً** (قيم وأنماط) ثم مقارنة دقيقة/بنيوية + تشابه بدل «±40 بايت» |
| البطاقة التجريبية بصيغة خاطئة | بطاقات الفحص تُولَّد **بنفس صيغة كروتك** |
| `KeyError` مع ملفات قديمة | `migrate()` يقرأ كل الصيغ القديمة ويتحقق قبل التشغيل (بلا انهيار) |
| `is_successful` لا يفهم 302 | قواعد قبول إيجابية صريحة + صفحة الحالة + **اختبار إنترنت فعلي** |
| كود ميت/مكرر | حُذف: ٣ ميزات غير مستخدمة، ودالة مكرّرة، وورد ٢٣٥٩ سطراً استُبدلت بحزمة منظّمة |
| يحتاج `pip install` | **مكتبة بايثون القياسية فقط** |
| توقف بلا تفسير | كل محاولة تصنَّف، وكل توقف له سبب مكتوب، و«الردود الغامضة» تُحفظ للمراجعة |

### اعتراف هندسي مفيد

أثناء بناء النسخة الجديدة، كشف **الاختبار الذاتي** نفسه عطلاً حقيقياً في الكود
الجديد: خيط التغذية كان يتوقف (deadlock) عند امتلاء الطابور بعد ظهور الحجب،
فيبقى التشغيل معلّقاً إلى الأبد — نفس صنف المشكلة التي عانيت منها. المصلح
موجود الآن، والاختبار `dead_target_is_detected_and_stops_the_run` يمنع رجوعه.
لهذا أضفت أمر `--selftest`: لكي تثبت الأداة نفسها لك قبل أن تثق بها.

---

## كيف تتأكد بنفسك في دقيقة

```bash
python3 KiraPass.py --selftest
```

١٣ سيناريو على راوترات وهمية: بطاقة صحيحة، ٥٠ بطاقة خاطئة (يجب ألا تُعلن أي
منها ناجحة)، حجب، تقييد 429، انقطاع اتصال، تشفير md5، بوابة GET، ملف تعريف
قديم… إن ظهر `ALL GOOD` فالأداة سليمة على جهازك.
