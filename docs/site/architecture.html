إقلاع الصفحة

  1. ui.html يُحمَّل، ثم ui.js في آخر <body>.
  2. دالة boot() (IIFE في آخر الملف) تستدعي api("/api/meta"): الإصدار، اللغة المحفوظة، الأبجديات charsets، أوضاع كلمة المرور pass_modes، القيم الافتراضية، الإعدادات الجاهزة presets، معلومات الكاش، قائمة البروفايلات، وهل الواجهة مفتوحة على الشبكة lan_open.
  3. buildSelects() تبني القوائم المنسدلة من meta، setLang() تطبّق الترجمة على كل عنصر له data-i18n وتضبط dir، ثم wire() تربط كل الأزرار.

مهم: data-i18n="key" في HTML هو النص الاحتياطي؛ القيمة الفعلية تأتي من I18N[LANG][key] في ui.js. أي نص تغيّره يجب أن يُغيَّر في المكانين (عربي/إنجليزي) — انظر النصوص المعروضة.

رحلة التشغيل: POST /api/run/start

أ) التجهيز (Engine.start)

  1. رفض إن كان state == "running".
  2. store.migrate(profile) ثم validate(): أي مشكلة صلبة ⇒ {"ok": false, "error": "profile_invalid"} (HTTP 400).
  3. إن كان resume=False: تصفير space_pos/walk_a/walk_b.
  4. حساب total = أدنى(المحاولات المطلوبة، الباقي في هذا المرور).
  5. تصفير كل العدّادات والأحداث (events.clear() حتى لا تُعرض نتائج التشغيل السابق).
  6. الحالة ← calibrating، وإطلاق الخيط kirapass-engine بدالة _run.

شجرة قرار الحكم (Judge.classify)

الترتيب مقصود: الحجب أولاً، ثم الرفض، ثم الأدلة الإيجابية، ثم «غير واضح».

1. هل هذه صفحة حماية؟
   ├─ عبارة من BAN_WORDS (مطابقة كلمة كاملة) أو HTTP 403/429/503
   │   ├─ 429 أو عبارة rate limit/slow down ──▶ RATE_LIMITED  (سبب: http_429 / ban_page)
   │   ├─ 503 بدون عبارة حجب            ──▶ RATE_LIMITED  (سبب: http_503)  ← لا نكذب على المستخدم
   │   └─ غير ذلك                       ──▶ BANNED        (سبب: ban_page / http_403)
   └─ لا ⇒ ننتقل للخطوة التالية

2. fp.same_as_reject(resp, extra_literals=القيم التي أرسلناها)
   ├─ «مطابق» + لكنه تحويل خارج البوابة  ──▶ UNKNOWN (redirect_out_of_portal_but_page_matches)
   ├─ «مطابق» + فيه كلمات نجاح متعلَّمة   ──▶ UNKNOWN (looks_rejected_but_success_words_found)
   └─ «مطابق»                            ──▶ REJECTED (same_as_rejection_page_exact/shape/similar/empty/redirect)

3. فيه captcha/g-recaptcha/hcaptcha      ──▶ CHALLENGE (captcha_present)

4. تحويل (redirect)؟
   ├─ المضيف ≠ مضيف البوابة
   │    ├─ فيه علامة من EXIT_HOST_MARKERS ──▶ ACCEPTED 0.95 (redirect_out_of_portal)
   │    ├─ فيه كلمة من PORTAL_URL_WORDS   ──▶ UNKNOWN (redirect_to_another_portal_page)
   │    └─ غير ذلك                       ──▶ ACCEPTED 0.85 (redirect_out_of_portal)
   ├─ التحويل ≠ تحويل الرفض المعروف       ──▶ ACCEPTED 0.70 (redirect_differs_from_rejection)
   └─ success_url_contains موجود         ──▶ ACCEPTED 0.90 (success_url_contains)

5. كلمات نجاح متعلَّمة + لا عبارات رفض    ──▶ ACCEPTED 0.6–0.9 (learned_success_words)
6. success_url_contains في رابط الرد      ──▶ ACCEPTED 0.90 (success_url_contains)
7. كلمة ترحيب فريدة (ACCEPT_WORDS)        ──▶ ACCEPTED 0.70 (welcome_words)
8. عبارة رفض موجودة (صفحة رفض متغيّرة)    ──▶ REJECTED 0.75 (rejection_wording)
9. غير ذلك                                ──▶ UNKNOWN 0.0 (reply_differs_not_proven) + كلمات الفرق

كيف يُقارَن الرد بصفحة الرفض؟ (Fingerprinter)

  1. التعلّم: learn_dynamic(bodies) تُخرج القيم الحرفية التي تختلف بين صفحتَي رفض (رمز جلسة، صدى الكرت، وقت…) — حتى 4 جولات.
  2. learn_patterns(bodies) تحوّلها إلى أنماط (\b[0-9a-fA-F]{8}\b) لأن القيمة نفسها لا تتكرر.
  3. بعد الإخفاء: إن تطابقت كل النسخ ⇒ exact = True ويُحفظ reject_masked_sha (مقارنة دقيقة بـ SHA-256).
  4. وإلا ⇒ reject_tokens = struct_tokens(...) (شكل الصفحة فقط) وتُستخدم نسبة تشابه difflib: ≥0.995 ⇒ رفض «shape»، وإلا مع تساوي الحالة و≥0.97 ⇒ «similar».
  5. الصفحات الفارغة: تُقارن بمفتاح التحويل _loc_key() (scheme+host+path فقط) أو بالحالة، ولا تُعتبر «مطابقة» بمجرد الفراغ.

المراقب: عندما يكذب الراوتر

بعض الراوترات تُدخل الضيف ثم تردّ بصفحة الرفض نفسها. الحكم وحده لا يرى النجاح. لذلك _start_watchdog() يشغّل خيط kirapass-watchdog يفحص كل WATCH_EVERY_SECONDS = 3 ثوانٍ: هل ما زلنا خلف الجدار؟

  • يعمل فقط إن كانت الحالة قبل التشغيل WALLED وWATCH_INTERNET وverify_enabled.
  • كل بطاقة تُرسل تُضاف إلى _since_check؛ وإن لم يفتح الإنترنت تُفرَّغ (لم تكن هي السبب).
  • عند ONLINE: تُنسخ القائمة كـمشتبه بها (حتى WATCH_SUSPECTS = 40 بطاقة)، ويُصدر حدث internet_opened، ويتوقف التشغيل بـ stop_reason="internet_opened".
  • الصفحة تعرض المشتبه بها وتطلب من المستخدم تجريبها واحداً واحداً — لا تدّعي معرفة أيها الصحيح.

رحلة المسجّل المنقّح

ui.js startCapture()
 ├─ window.open("about:blank")            ← داخل إيماءة النقر (حتى لا يُمنع المنبثق)
 ├─ POST /api/capture/start {url}
 │    └─ Hub.start() → Capture(url, guard) → _exchange("GET", start_url)
 ├─ popup.location = /capture/view?id=…   ← capture.view_page() تبني صفحة VIEW_PAGE
 │
 │  داخل صفحة المسجّل:
 │  ├─ iframe sandbox="allow-scripts allow-forms"  (بلا allow-same-origin)
 │  ├─ srcdoc = rewrite_html(page)         ← يحقن <base> + CSP + window.__KP__ + INTERCEPTOR
 │  ├─ INTERCEPTOR يعترض: submit / HTMLFormElement.submit / نقرات <a> / fetch / XHR
 │  │    └─ postMessage إلى الصفحة الأم (ولا يرسل شيئاً إلى البوابة أو إلى API الأداة)
 │  ├─ الأم تستدعي POST /api/capture/step
 │  │    └─ Hub.step() → Capture._exchange() بجلسة سيرفر تحتفظ بالكوكي والرموز
 │  │       ├─ _learn_password(before, after) → infer_pass_mode()
 │  │       └─ يعيد frame_body لطلبات fetch/XHR أو html_view محدّثاً للتنقل
 │  ├─ POST /api/capture/mark {success|reject|status}
 │  │    └─ learn_words() على نص <body> المرئي فقط (لا meta ولا script)
 │  └─ POST /api/capture/finish
 │       └─ _build_report() + _build_profile() → Store.save_run() + Store.put()
 └─ تنزيل التقرير (GET /api/capture/report?download=1)

كل مخرجات هذه الرحلة منقّحة: redact_fields (أطوال وتصنيفات بدل القيم)، safe_url (مفاتيح الاستعلام بدل قيمها)، _strip_hop (أسماء الكوكيز)، custom_header_names (أسماء الترويسات)، _scrub (حذف أي قيمة سرّية رُصدت من كامل JSON)، وexport_curl (أمر curl بقيم <redacted>).
